# 区分确定性操作、智能体建议卡片和上下文对话

产品采用三层呈现模型，不把所有主动干预或状态操作包装成 Agent 对话。

## 确定性操作面板

“立即开始”“我已经开始”“我已经完成”等由领域规则提供的明确状态转换必须立即可用，不调用 LLM，也不因模型或供应商暂时不可用而阻塞。准备提示、会话检查点的基本状态选择、收尾确认、执行补记、复盘入口和再触达日期计算同样属于确定性能力。

## 智能体建议卡片

一轮即可表达清楚的建议使用主窗口中的非模态建议卡片，例如缩小后的下一步行动、追加工作候选或具体改期方案。卡片至少呈现推荐内容、简短依据及其对当前安排的影响，并提供“接受”“修改后接受”和“不采用”；建议不得因生成或展示而直接生效。

## 上下文对话

存在缺失信息或需要多轮澄清的场景使用主窗口中的上下文对话，例如方案导入、阻碍支持、日终复盘和重新进入流程。对话必须携带相应用户方案、下一步行动或执行状态的引用，不能把模型会话本身作为领域状态来源。是否使用模态容器由后续交互规则决定，“上下文对话”本身不等于强制模态框。

## 气泡与外部渠道

应用内气泡只表示有一项可查看的建议并提供上下文入口，不承载完整建议，不允许复杂建议从气泡中直接生效，也不使用未读数量制造建议积压感。系统通知和邮件只负责送达或进入正确上下文，不承载完整 AI 建议及其确认流程。具体场景与呈现载体的映射继续由 Issue #1 和 Issue #2 跟踪。
