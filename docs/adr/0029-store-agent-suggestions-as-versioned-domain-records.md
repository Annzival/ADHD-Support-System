# 将智能体建议保存为带状态版本的领域记录

每项智能体建议都由应用保存为供应商无关的结构化领域记录，不能只存在于聊天文本、模型上下文或供应商专有运行状态中。PydanticAI 负责把模型输出校验为应用定义的结构化结果；智能体核心负责补充权威标识和版本信息、持久化记录并控制后续状态转换。

## 记录内容

建议记录至少包含：

- 建议标识、类型、触发原因和创建时间；
- 关联的用户方案、下一步行动或执行状态，以及生成时所依据的状态版本；
- 机器可读的建议内容和面向用户的简短依据；
- 引用的执行证据、显式假设、缺失信息和不确定之处；
- 对用户方案、当天执行安排和执行状态的影响范围；
- 是否需要确认、允许的用户操作、有效期或其他失效条件，以及当前生命周期状态；
- 用于审计和评估的模型供应商、模型、提示版本和输出模式版本。

生成来源等审计字段默认不占用面向用户的建议界面。系统不保存或展示模型的隐藏推理过程，也不生成缺乏校准依据的数字置信度；面向用户的不确定性通过假设、未知信息和风险表达。

## 呈现与应用

ADR-0028 定义的智能体建议卡片和上下文对话是建议记录的不同视图，不是彼此独立的状态源。更换 API key、模型或供应商后，既有建议及其接受、修改、拒绝记录必须继续可用。

用户接受建议时，智能体核心通过确定性领域命令再次验证目标状态版本和业务约束后再应用修改，LLM 不直接写入权威状态。相关状态已经改变时，旧建议必须被阻止直接应用并标明可能已经过期；具体生命周期状态及延后处理规则另行决定。
