# 在结构化工作区审阅方案导入草案

用户导入文本或 Markdown 后，应用立即保存方案原文，并显示可退出的处理状态。Agent 生成方案导入草案后，主窗口通过方案审阅工作区分别呈现原文明确内容、Agent 派生的任务拆分或时间分配，以及缺失、冲突或不确定信息；具体采用并排还是切换布局留给后续交互设计。

每项派生内容必须能够追溯到相应原文，没有原文依据的假设单独标出。用户可以直接编辑草案，也可以针对具体条目请求解释或重新生成，不需要通过多轮对话完成全部修改。只有阻止形成可执行安排的关键缺口必须在启用前解决；其他不确定信息可以明确保留为待以后确认。Agent 不得自行补充目标、截止日期或优先级。

## 生命周期与渠道

用户修改方案原文后，基于旧版本原文且仍未确认的建议标记为已被取代，不得覆盖用户编辑。草案可以保存并稍后继续；未启用前不触发任务调度或主动干预。方案导入是用户主动发起的流程，不使用气泡、系统通知、置顶小窗或邮件请求注意。

## 启用确认

用户选择启用方案后，确定性变更确认界面展示将创建或更新的下一步行动、时间安排、仍保留的不确定信息，以及原文内容与 Agent 派生内容的区别。只有用户最终确认后，结构化草案才成为权威用户方案。
