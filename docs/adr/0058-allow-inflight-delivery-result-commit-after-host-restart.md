# 允许通过存续检查的原事务在宿主重启后完成保存

两轮隔离实验及 `baf72b1` 研究表明，当前机制不能把宿主重启与 SQLite 提交不可分割地协调；用户明确接受有限放宽，以避免为历史设备报告扩张启动仲裁架构。本决定仅替代 ADR-0057 中“宿主重启前未提交结果一律不得在重启后保存”的绝对边界，其余历史追加、不重发、不恢复旧操作及未知顺序规则继续有效。

原 Core 在同一结果事务内核对此前允许发送的同一次尝试、对应设备结果及原宿主进程实例，并在提交前最后一次可靠存续检查中确认旧实例仍存活后，允许**该笔仍在进行的事务**完成保存，即使随后旧宿主退出、新宿主已运行。检查时已发现原实例退出、无法可靠确认身份或存续、或关联不符时，仍拒绝新增结果。取得发送许可、收到请求、缓存过一次检查成功，都不能代替这笔事务中的核验。

资格不跨事务继承：事务回滚或未提交失败后的新请求须重新核验；新宿主不得因此重建旧结果。Core 自身重启后仍不补存旧未提交结果；是否已提交以恢复后的数据库为准。已提交且内容一致的原命令继续返回原结果，不要求旧宿主仍存活，不新增事实。关闭窗口但进程仍运行不算重启。

代价是历史中可能多保存原严格规则会拒绝的设备报告，检查到提交没有已证明的最大时长；不承诺只有几毫秒，也不伪造超时上限。追加不重发通知、不恢复旧按钮、不改变任务／会话／调度；设备成功不证明用户看见，顺序及机会资格未知时仍不增加合格机会或计算精确延迟。报告、事实及命令结果仍按 ADR-0055 同事务保存。

两轮 FAIL 是当时规则下的有效结论，不回写成 PASS。新规则须另行验证，尤其是原进程实例的可靠绑定与锁定 Windows 行为；本决定不是实现完成或 Windows 验收通过。
