# 允许有限追加历史送达事实，但不恢复旧操作

状态：部分被 [ADR-0058](0058-allow-inflight-delivery-result-commit-after-host-restart.md)替代。下文保留原重启决定以追溯两轮 FAIL；当前宿主重启边界允许通过检查的原事务完成保存，以 ADR-0058 为准。Core 重启限制及本 ADR 其余不变量不变。

I-02 的交错复现表明：设备报告发送成功后，若用户先开始行动、送达回执后保存，现有规则会取消该尝试并拒绝回执，使保存结果取决于请求先后顺序。用户确认允许有限追加这类历史设备事实，而不是一律丢弃；前提是能核对它属于此前经 Core 校验允许呈现的同一次尝试，并有对应的设备结果依据，不能从用户点击或开始行动反推通知已送达。

追加结果只记录此前发生的事：不重新发送提醒、不恢复旧按钮、不重开干预、不改变已建立的会话；同次结果只保存一次，同一逻辑干预不重复计数。设备报告成功不证明用户看见或在场；呈现发生时间与 Core 接收时间必须区分，不能以迟到的接收时间计算进入延迟，资格或先后无法确认时保持未知，不强行计入合格机会或生成精确延迟。

## 与现有决定的关系

补充 ADR-0052 中“未执行尝试失效”和 A02 的历史结果接纳边界，不废弃它们；普通旧用户操作仍按当前状态及版本拒绝。ADR-0055 的事务与幂等要求继续适用，不能以本决定为由跳过所有版本校验或覆盖已保存事实。

## 原先确认的重启边界（宿主部分已由 ADR-0058 调整）

用户进一步确认：Core 或桌面宿主任一进程重启后，不补存重启前尚未由 Core 提交保存的设备发送结果，不因此重发通知；缺失结果保持未知，不写成发送失败、用户未执行或合格机会。这里的“已保存”指设备结果及对应命令结果已由 Core 事务提交，仅保存过发送许可不算已保存发送结果。关闭窗口但进程仍在托盘运行不属于重启。

已提交的设备结果、任务和执行会话等持久记录正常保留；结果已提交但响应丢失时，重启后重试同一命令 ID 仍返回原处理结果，不新增事实或重复计数。该取舍只限制未提交设备结果的跨重启补存，不取消既有状态及调度恢复规则，也不要求为了补证重新呈现通知。

相较跨重启恢复未提交结果，首版接受崩溃窗口内部分真实发送无法补证的代价，暂不增加为此服务的宿主持久待交回记录及跨重启核对机制。后续观察须披露这类证据缺口；不能用缺失值生成精确进入延迟。

## 同一运行期内顺序不明的结果

用户进一步确认：Core 与宿主均未重启时，若 Core 能将设备发送结果核对到此前允许发送的同一次尝试，即使无法证明发送与用户回应的先后，也保存设备报告；顺序及机会资格保持未知，不据此增加合格机会、计算精确进入延迟或认定通知促成了开始。不丢弃有依据的设备报告，也不以它恢复旧操作、重发通知或改变已开始的会话。

“不能确定先后”和“不能对应同一次发送”不同：本次只接受前者，不接受无对应许可、仅有用户点击或无法关联尝试的报告成为权威送达事实。保存历史报告不授予新的发送权限；未执行尝试的取消规则仍然适用。

## 剩余技术验证

产品取舍已确认，暂停该项 grilling；剩余工作是验证 Core 如何核对许可与同次设备调用、区分进程重启，以及哪些记录确实能证明顺序。PR #35 推荐的运行标识、序号和时钟字段仍是候选机制，不因本次接受自动成为已经验证的协议或时间判据。现有四支合成回调诊断不能证明真实 Windows 呈现时刻。技术执行者按[有界验证交接](../implementation/plans/i02-g01-verification-handoff.md)生产证据；如果机制不能满足上述边界，回传证据，不自行扩大接纳范围。

证据：Issue #33、Draft PR #35（`7834bdb`）的四支诊断，原生通知使用替身，不是 Windows 实测；其观察结果不自动成为验收预期。用户在本治理对话明确接受“允许有限追加，且不恢复旧操作”。
