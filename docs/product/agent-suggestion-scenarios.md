# 智能体建议场景矩阵

本文汇总 v0.1 已确认的智能体建议触发场景与信息需求，供交互设计、状态建模和验收使用。通用记录结构、生命周期和注意规则分别见 ADR-0029、ADR-0030 和 ADR-0031；所有建议都必须遵守用户确认、干预策略和供应商无关状态边界。

## 场景矩阵

### 1. 方案导入与审阅

- **触发条件**：用户导入方案原文，或对方案导入草案中的具体条目请求解释或重新生成。
- **上下文输入**：带版本的方案原文、原文中明确的目标与约束、现有草案、用户编辑和仍待解决的缺口。
- **建议内容**：任务拆分、时间分配、估时、缺失或冲突信息；每项派生内容关联原文依据，无依据假设单独标出。
- **授权边界**：只修改非权威草案；不得自行补充目标、截止日期或优先级。最终确认前不得调度或触发主动干预。
- **有效期**：方案原文或用户编辑发生相关变化后，未确认建议被取代。
- **响应要求**：草案可以保存并稍后继续；只有启用用户方案时必须完成确定性变更确认。
- **呈现层级与渠道**：方案审阅工作区、局部智能体建议卡片或上下文对话；不使用气泡、置顶小窗、系统通知或邮件请求注意。见 ADR-0015、ADR-0035。

### 2. 通用可行性分析

- **触发条件**：用户通过方案中的显式入口主动请求；用户方案启用或实质修改；截止日期、依赖、可用时间或关键执行证据变化；执行空档产生实质影响。
- **上下文输入**：已启用用户方案、剩余工作、截止日期、依赖关系、可用时间、已确认安排、估时、实际用时和信息缺口。
- **建议内容**：最多突出三个确定冲突、可行性风险或信息不足事项，并为每项提供最多三个拆分、估时、时间分配、顺序或暂停候选。
- **授权边界**：不得制定新的学习或求职策略，不得直接修改用户方案。
- **有效期**：相关用户方案、依赖数据或执行证据变化后被取代。
- **响应要求**：分析本身无需回应；应用调整候选时必须进行确定性变更确认。
- **呈现层级与渠道**：用户主动请求时在方案上下文呈现；后台首次发现新实质风险时可以发起一次非阻塞建议注意请求；没有新问题时不发送通知。见 ADR-0040。

### 3. 难以开始或执行中遇阻

- **触发条件**：用户主动选择“现在有点难开始”或“请求阻碍支持”。
- **上下文输入**：当前下一步行动、预计时长、执行会话、恢复包、现有安排，以及至多一个会实质改变首项建议的补充答案。
- **建议内容**：一项足够小的首项建议，明确属于缩小下一步行动、调整执行方式、改期、暂停并保存恢复包或今天不继续。
- **授权边界**：不要求完整原因，不作心理诊断；修改用户方案时另行形成方案调整建议。
- **有效期**：相关下一步行动或执行会话状态变化后过期或被取代。
- **响应要求**：补充问题可以选择记不清、不确定或跳过；得到首项建议后，用户自行决定是否深入对话。
- **呈现层级与渠道**：立即进入主窗口上下文，并保留确定性退路；不另发气泡、系统通知或邮件。见 ADR-0025、ADR-0034。

### 4. 剩余精力

- **触发条件**：用户在收尾确认中报告还有精力。
- **上下文输入**：当前可用时间或精力范围、下一个已确认安排、已确认用户方案及依赖状态。
- **建议内容**：最多三个方案内候选，优先为短小收尾、降低下次启动成本的准备行动或适合前置的后续行动；始终保留平等的“到此结束”。
- **授权边界**：不得自动增加工作、延长允许工作时段或制定新策略。
- **有效期**：当前可用时间结束、下一个已确认安排开始或相关用户方案状态变化。
- **响应要求**：用户可以关闭或选择到此结束而不被追问；采用候选前必须进行确定性变更确认。
- **呈现层级与渠道**：收尾确认当前上下文中的单张建议卡片；不另发气泡、系统通知或邮件。见 ADR-0014、ADR-0023、ADR-0036。

### 5. 日终复盘与补记日终复盘

- **触发条件**：用户进入日终复盘或补记日终复盘，并完成或跳过事实核对。
- **上下文输入**：当天确定性执行摘要、用户修正、执行证据、未知状态、估时与实际用时、当天安排调整和当前用户方案。
- **建议内容**：最多三项区分观察依据、未知信息和后续建议的分析；估时、改期或用户方案变化以独立方案调整建议呈现。
- **授权边界**：未知不得写成未执行；不作心理诊断，不用单日数据推断稳定人格；完成复盘不等于接受建议。
- **有效期**：相关执行证据或用户方案状态变化后被取代；补记产生的建议只能依据当前状态。
- **响应要求**：问题允许跳过或记不清；模型不可用时仍可保存事实并完成复盘。
- **呈现层级与渠道**：确定性摘要、有限 Agent 分析和独立建议卡片；复盘完成后不为每条建议另发气泡、系统通知或邮件。见 ADR-0024、ADR-0037。

### 6. 执行空档后的重新进入

- **触发条件**：用户主动返回应用，并确认存在执行空档；或从本机恢复入口进入流程。
- **上下文输入**：最后执行状态、恢复包、期间执行事实与未知信息、当前时间、用户方案、截止日期、依赖和安排影响。
- **建议内容**：推荐一个当前入口，同时保留继续原下一步行动、缩小后开始、改期、暂停用户方案和今天暂不恢复五个确定性选择。
- **授权边界**：不展示积压清单，不要求逐日追溯或先解释空档原因；不得复活旧建议、旧通知或旧安排。
- **有效期**：跨过用户本地自然日或依赖状态变化后重新生成。
- **响应要求**：期间执行核对可以记不清或跳过；只有确认新入口后才创建安排并恢复主动干预。
- **呈现层级与渠道**：主窗口重新进入流程；本机入口可以直接定位。v0.1 邮件只提示用户自行打开 PC 应用，不提供邮件深链。见 ADR-0017、ADR-0018、ADR-0038。

### 7. 干预策略冲突

- **触发条件**：启用或修改用户方案、执行安排或干预策略时，确定性规则发现所需主动支持落入禁止联系的时间或渠道。
- **上下文输入**：执行安排、准备提示或开始干预或检查点需求、允许联系时段与渠道、安静时段。
- **建议内容**：用户从三个确定性操作中选择改期后，Agent 最多提供三个符合当前约束的时间候选；保留执行时间但没有主动干预、改期和用户主动修改干预策略本身不是 Agent 建议。
- **授权边界**：冲突不阻止用户主动执行；不得自动改期、扩大联系权限或因紧迫性绕过安静时段。
- **有效期**：相关执行安排或干预策略变化后被取代。
- **响应要求**：可以暂不处理并保存安排，但必须显示该时段没有主动干预。
- **呈现层级与渠道**：编辑流程中的非模态冲突卡片；同一冲突不反复发送气泡或通知；修改策略进入确定性设置界面。见 ADR-0019、ADR-0039。

## 跨场景建议类型

方案调整建议不是独立触发场景，也不从属于日终复盘。方案审阅、通用可行性分析、阻碍支持、日终复盘、重新进入和干预策略冲突都可能产生方案调整建议。它只能调整用户已经提供的方案结构、估时、时间分配、顺序或暂停状态，不能制定底层学习或求职策略；应用前必须经过用户确认和确定性领域命令校验。

## 不属于智能体建议的确定性能力

以下能力可以提供固定操作或触发 Agent 支持入口，但本身不是 Agent 生成的建议：

- 准备提示、开始干预及其一次低强度跟进；
- “立即开始”“我已经开始”“我已经完成”“改到具体时间”和“今天不做”等状态操作；
- 会话检查点、收尾确认、执行补记和期间执行核对；
- 日终复盘邀请与补记入口；
- 邮件再触达日期计算、干预取消和失效判断；
- 设备恢复后依据当前状态合并生成的恢复干预及其固定操作；需要生成缩小步骤时进入阻碍支持场景；
- 干预策略冲突检测和通用可行性分析中的确定性检查；
- 变更确认及最终领域命令执行。

模型不可用时，这些确定性能力必须继续工作；缺少 Agent 候选不能阻塞用户退出、改期、暂停、记录事实或自行执行。
