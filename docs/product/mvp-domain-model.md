# 首个 MVP 核心领域模型

## 目的与范围

本文档逐步固定必要设置切片和首要执行闭环所需的最小领域对象、权威状态、命令、事件、状态转换与非法转换。它只覆盖首个 MVP，不把 MVP 后的完整方案调整、日终复盘、阻碍支持或多日重新进入引入当前模型。

智能体核心是唯一权威状态源。桌面客户端、桌面宿主、LLM 对话和模型供应商状态均不拥有或直接修改下述领域状态。

## 已确认的方案权威边界

| 领域对象 | 权威性 | 已确认关系 |
| --- | --- | --- |
| 方案原文 | 非权威 | 保留用户输入及其版本，作为草案内容的追溯依据 |
| 方案导入草案 | 非权威 | 可以保存、编辑、重新生成或被新版原文取代；不能触发调度或主动干预 |
| 用户方案 | 权威身份 | 关联其历次用户方案版本，并指出唯一的当前版本 |
| 用户方案版本 | 权威且不可变 | 只在用户最终确认后发布；后续调整发布新版本，不覆盖旧版本 |
| 首项下一步行动及执行安排 | 权威 | 与用户方案版本在同一次方案启用中建立；不得先于方案版本单独生效 |

方案启用遵守以下不变量：

1. 用户最终确认之前，方案原文和方案导入草案都不能成为权威用户方案；
2. 一次成功启用同时发布不可变的用户方案版本、设为当前版本，并建立首项下一步行动及执行安排；
3. 版本冲突或持久化失败使整次启用失败，不得出现部分方案已经启用或调度先行生效；
4. 后续用户方案版本不能改写旧执行安排、执行会话或执行证据所引用的历史依据；
5. Agent 和 LLM 只能生成或修改非权威草案，不能直接发布用户方案版本或移动当前版本。

该决定由 ADR-0043 记录。首个 MVP 可以只围绕当前用户方案版本构建执行闭环，但领域关系不依赖模型供应商，也不把草案本身提升为权威对象。

## 已确认的行动固化边界

“已完成的方案部分固化”在首个 MVP 中规范为固化确切行动及其历史执行事实，而不是锁定整个用户方案分支：

1. 用户明确报告完成，并完成或跳过收尾确认后，当时用户方案版本中的确切下一步行动、执行安排和执行证据成为不可回写的历史事实；
2. 后续用户方案版本可以调整尚未完成的内容，但不得回溯修改已完成行动的名称、范围、来源或结果，也不得把“完成初稿”等事实改写为“完成终稿”；
3. 部分完成只固化本次实际进展和执行证据，不把整个下一步行动标记为完成；同一下一步行动仍可再次安排；
4. 如果用户改变剩余工作的范围，由新的用户方案版本表达，不修改原行动及其历史证据；
5. 历史事实有误时追加执行事实更正，记录更正内容、原因和时间，原执行证据继续保留；
6. 新用户方案版本可以引用已完成事实作为历史依据，但不能重新解释或覆盖这些事实。

该边界由 ADR-0044 记录。它不要求首个 MVP 引入方案树、已完成分支锁或用户可见的“锁定”功能。

## 已确认的行动与安排身份

下一步行动和执行安排是不同的权威对象：

| 对象 | 回答的问题 | 身份与版本关系 |
| --- | --- | --- |
| 下一步行动 | 要做什么 | 固定属于确切用户方案版本；内容或范围改变时由新用户方案版本表达 |
| 执行安排 | 何时尝试 | 引用确切下一步行动；保存计划开始时间、可选执行窗口和预计时长 |

执行安排遵守以下不变量：

1. 同一下一步行动同时最多只有一个能够触发开始干预的当前执行安排；历史安排可以继续存在；
2. “改到具体时间”原子地把旧执行安排结束为已改期，并创建引用同一下一步行动的后继执行安排；
3. 旧执行安排、原计划时间和相关开始干预继续作为历史保留，但不能在后继安排生效后再次触发；
4. 部分完成没有改变行动范围时，可以为同一下一步行动建立新的执行安排；
5. 行动内容或范围发生改变时，必须由新用户方案版本中的下一步行动表达，不能通过改期或覆盖执行安排实现；
6. 改期事务失败时，旧安排保持原状，不得只结束旧安排或只创建后继安排。

该边界由 ADR-0045 记录。具体数据库键、表结构和调度实现不属于领域决定。

## 已确认的执行会话活动边界

首个 MVP 的执行会话使用以下最小生命周期：

```text
不存在执行会话
  → 用户确认所需时长
  → [执行中：会话与首次检查点原子建立，占用唯一活动会话位置]
      ├─ 用户报告完成或暂停
      │    → [等待收尾：检查点失效，继续占用唯一活动会话位置]
      │         → 用户完成或跳过收尾
      │         → [已结束：原子保存最小执行证据和必要恢复包，释放位置]
      └─ 检查点无回应达到保留期限
           → [会话跟踪结束、结果未确认：不形成执行证据，释放位置]
```

状态转换遵守以下不变量：

1. “执行中”和“等待收尾”都占用同一个唯一活动会话位置，二者存在时不得建立或恢复第二个执行会话；
2. 用户报告完成或暂停后，原会话检查点立即失效，不再触发检查或续行操作；
3. 完成或跳过收尾时，最小执行证据、必要恢复包、会话结束和活动位置释放属于同一个原子转换；
4. 用户跳过收尾时，根据此前明确的完成或暂停操作保存一致的最小执行证据，不要求补齐可选字段；
5. 检查点无回应达到保留期限时，记录会话跟踪结束和未确认执行状态，不进入收尾、不形成执行证据或恢复包，也不把现实执行标记为结束；
6. 应用重启不能通过丢弃“等待收尾”状态释放活动位置；长期无回应只按下述自动跳过规则退出。

该边界由 ADR-0046 记录。收尾确认不是日终复盘，也不为首个 MVP 引入剩余精力扩展或下一项工作。

### 等待收尾无回应

等待收尾采用不新增提醒的被动退出规则：

1. 用户关闭收尾界面，明确视为跳过收尾；
2. 没有操作时，自动跳过边界取以下适用时刻中的最早者：原执行窗口结束、下一项计划工作需要成为前台执行上下文、没有前两者时用户本地时区次日 00:00；
3. 边界到达后，系统只依据此前明确的完成或暂停操作保存最小执行证据；实际用时、额外完成程度、剩余精力等未确认字段保持未知；
4. 暂停时保留已经形成的最小恢复包，不因自动跳过补写用户未提供的内容；
5. 最小执行证据、必要恢复包、会话结束和活动位置释放仍在同一个原子转换中完成；
6. 应用重启时，未到边界则恢复等待收尾；已经到达边界则幂等执行一次自动跳过，不重复产生证据；
7. 自动跳过不是自动完成、超时失败或对现实执行状态的新推断。

该规则由 ADR-0047 记录。它复用既有时间和前台竞争边界，不增加固定的收尾倒计时参数。

## 已确认的会话检查点身份

会话检查点属于一个执行会话，并以不可回写的后继链表达多次续行：

```text
执行会话
  └─ 检查点 1（已回应并继续）
       └─ 检查点 2（已回应并继续）
            └─ 检查点 3（当前）
```

检查点遵守以下不变量：

1. 每个检查点记录一次用户确认的具体检查时间，不通过修改原时间表达续行；
2. 用户选择继续并确认新检查时间时，当前检查点结束为“已回应并继续”，并在同一原子转换中创建唯一后继检查点；
3. 续行保持原执行会话及其活动位置，不创建新的执行会话；
4. 同一执行会话同时最多只有一个能够触发状态核对的当前检查点；
5. 已处理检查点继续保留原计划时间、送达情况和用户选择，但不得再次触发；
6. 检查点无回应不能自动创建后继检查点；只有用户明确确认新的检查时间才能续行；
7. 重复提交同一次续行操作必须幂等，不能创建多个后继检查点或重复失效当前检查点。

该边界由 ADR-0048 记录。具体提醒调度和持久化结构仍由实现决定，但不能破坏唯一当前检查点和历史不可回写约束。

## 已确认的暂停与恢复关系

暂停稳定结束一次执行尝试；恢复基于恢复包创建新的关联执行会话，而不重新打开原会话：

```text
执行会话 A
  → 暂停
  → 完成或跳过收尾
  → 会话 A 已结束 + 恢复包 A
       → 用户选择继续并确认剩余预计时长
       → 新执行安排 B + 执行会话 B + 首次检查点 B
       → 恢复包 A 已被会话 B 使用
```

暂停与恢复遵守以下不变量：

1. 暂停并完成或跳过收尾后，原执行会话保持已结束，不能重新打开或附加新的检查点；
2. 恢复包引用原执行会话、确切用户方案版本、下一步行动和已取得进展，在收尾结束时与最小执行证据一起固化；
3. 用户选择继续上次执行时，必须确认本次剩余预计时长，不能直接从旧检查点继续计时；
4. 恢复成功时，新执行安排、新执行会话、首次检查点及“恢复包已被该会话使用”记录属于同一个原子转换；
5. 新执行安排从当前时间开始并引用同一下一步行动；原执行安排和会话继续作为历史保留；
6. 一个恢复包最多只能成功创建一个接续会话；重复提交必须返回同一结果，不能产生第二个活动会话；
7. 任一步失败时不消费恢复包，也不留下新安排、会话或检查点的部分状态；
8. 接续会话再次暂停时生成新的恢复包，并保留从新包到新会话、旧包和原会话的可追溯关系。

该边界由 ADR-0049 记录。恢复包指向的方案版本已经不再是当前版本时，继续遵守下述显式选择规则。

### 旧方案版本恢复包

恢复包保留暂停时的原始引用，不自动迁移到当前用户方案版本：

1. 方案版本变化后，恢复入口分别呈现上次暂停的确切行动和进展，以及当前方案中适用的行动；
2. 用户选择继续上次执行时，新执行安排和会话继续引用旧用户方案版本中的确切下一步行动；该操作不把旧版本设为当前版本，也不修改当前方案；
3. 用户选择按当前计划继续时，旧恢复包结束为未使用归档，不再主动出现；原暂停事实、进展和恢复包继续作为历史保留；
4. 未使用归档不表示旧行动已经完成、失败或放弃，也不删除它在旧方案版本中的历史；
5. 恢复包已经被接续会话使用、已经归档、目标行动已经由明确证据或执行事实更正确认为完成，或当前已有活动会话时，继续该恢复包属于非法转换；
6. 系统和 LLM 不得猜测新旧版本中的行动是否等价，也不得自动迁移或合并恢复包；行动范围变化继续由新方案版本表达；
7. 选择旧断点、选择当前计划或归档恢复包的转换必须基于当前版本和恢复包状态校验，重复提交不能创建额外会话或重复归档。

该边界由 ADR-0050 记录，并保持此前恢复干预中“从断点继续”与“按当前计划继续”的自主选择。

## B-03 当前状态

方案导入到权威版本、已完成行动固化、下一步行动与执行安排、执行会话活动边界、等待收尾退出、检查点续行及恢复包适用性已经固定。仍需依次确定：“我已经完成”在没有既有会话时的领域表示；其他事实、命令、事件及非法转换矩阵。
