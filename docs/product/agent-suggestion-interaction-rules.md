# 智能体建议交互规则

本文汇总智能体建议的通用呈现和交互规则。逐场景输入、输出、权限和有效期见 [智能体建议场景矩阵](agent-suggestion-scenarios.md)。

## 呈现层级

| 层级 | 用途 | LLM 依赖 | 允许直接改变状态 |
| --- | --- | --- | --- |
| 确定性操作面板 | 开始、完成、改期、暂停、事实核对等明确状态操作 | 否 | 通过确定性领域命令 |
| 智能体建议卡片 | 一轮可以表达清楚的有限建议 | 是 | 否，必须由用户采用 |
| 上下文对话 | 缺少信息或需要共同澄清的问题 | 是 | 否，对话不是权威状态源 |
| 变更确认 | 应用建议前展示差异、影响和取消操作 | 否 | 用户确认后由确定性领域命令执行 |

Agent 生成建议时不自动打开模态框或抢夺焦点。模态框只用于用户主动采用建议后、即将修改用户方案或当天执行安排时的最终变更确认。见 ADR-0028、ADR-0032。

## 建议记录与生命周期

每项建议以供应商无关的结构化领域记录保存，包含目标状态版本、结构化内容、简短依据、证据、假设、未知信息、影响、有效期、允许操作和生成溯源。应用不保存或展示模型隐藏推理，也不使用没有校准依据的数字置信度。见 ADR-0029。

决定状态、有效性状态和注意状态彼此独立：

- 决定：待决定、已接受、修改后接受、不采用；
- 有效性：有效、已过期、已被取代；
- 注意：未查看、已查看，以及可选的稍后处理时间。

关闭气泡只表示已查看。用户只有选择恢复时间后，系统才可以在该时间进行一次受干预策略约束的低强度提示。见 ADR-0030。

## 多建议与持久入口

同一目标和目的只保留一项有效建议；不同上下文中的建议不合并内容。同一时刻最多一项建议主动请求注意，优先级由智能体核心确定，用户处理后不连续弹出下一项。过期或被取代的建议不再请求注意。见 ADR-0031。

建议的权威入口位于关联的用户方案、下一步行动、日终复盘或重新进入流程。首页“需要你决定”区域只提供有效待决定建议的摘要导航，不显示红点或未读数量，也不构成建议收件箱。气泡、置顶小窗和系统通知必须深链到对应建议；邮件是否可用由具体场景决定。见 ADR-0033。

## 载体职责

| 载体 | 可以承担 | 不得承担 |
| --- | --- | --- |
| 主窗口 | 完整建议、上下文对话、事实核对、差异和变更确认 | 无用户操作时抢夺焦点 |
| 应用内气泡 | 一次建议注意请求和具体上下文入口 | 完整复杂建议、直接应用、未读数量 |
| 置顶小窗 | 当前执行转换和打开具体建议上下文 | 完整 Agent 对话或复杂确认 |
| 系统通知 | 送达和深链到具体本机上下文 | 完整建议、绕过干预策略 |
| 邮件 | 已明确允许场景中的再触达 | v0.1 深链本地应用、携带认证信息、直接确认建议 |

设备恢复后的恢复干预属于确定性能力，不进入智能体建议矩阵；其具体本机载体另行决定。恢复干预中的“生成缩小步骤”进入阻碍支持上下文。

## 应用、撤销与更正

用户采用建议后，确定性领域命令重新验证目标版本和业务约束。系统保存来源建议、变更前后状态、最终应用内容和命令结果。没有后续依赖时可以确定性撤销；已经产生依赖时改用手动或补偿性调整，不能破坏性回滚。用户报告的执行事实通过更正保存新版本，不使用撤销语义。见 ADR-0041。

## 键盘与焦点验收

- 后台建议和气泡不自动抢焦点；用户主动打开后聚焦建议标题。
- 所有内容和操作可以通过 Tab、Shift+Tab、Enter 和 Space 到达和执行。
- 操作完成或取消后返回原触发控件；控件消失时返回业务上下文标题。
- 变更确认限制焦点，Esc 取消，默认焦点在取消，关闭后返回发起控件。
- 状态使用文字表达，不只依赖颜色、图标或动画。
- 遵守系统减少动态效果设置，不使用闪烁或持续动画请求注意。
- 置顶小窗可以用键盘打开主窗口；快捷键不得成为唯一操作方式。

见 ADR-0042。
