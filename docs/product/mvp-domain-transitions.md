# 首个 MVP 命令、事件与状态转换矩阵

## 范围与阅读方法

本文把[核心领域模型](mvp-domain-model.md)、[构建就绪文档中的已确认路径](mvp-build-readiness.md)及 ADR-0043～0056 整理为转换清单，不新增未经确认的产品能力。它覆盖必要设置切片、开始、执行、收尾和恢复；末尾记录已补全的恢复转换及其确认来源。

表中的命令和事件使用描述性中文，不固定 API、代码标识符、表结构或事件拆分粒度。“事件”表示成功后可以记录的已发生事实，不等于执行证据；纯查看、打开界面和未完成确认不是成功领域转换。设置阶段的原文、草案即使被持久化，也仍是非权威内容。

所有权威转换统一遵守 ADR-0055：Core 校验命令身份、目标与预期版本，在同一事务中保存当前状态、事件、处理结果和必要调度。客户端只提交操作，LLM 只产生非权威内容。矩阵中同一行的联合结果不能部分成功。

## 一、必要设置切片

依据：构建就绪文档“必要设置切片”、ADR-0015、ADR-0035、ADR-0043。

| ID | 触发者与操作 | 前置条件 | 保存结果或事实 | 拒绝条件／不发生的事 |
| --- | --- | --- | --- | --- |
| S01 | 用户导入文本或 Markdown | 用户提供既有方案 | 保存方案原文及可继续处理的工作区 | 不发布方案、不创建执行调度 |
| S02 | Agent 返回结构化草案，Core 保存 | 结果对应所引用的原文版本 | 草案保留原文依据，区分原文、派生内容和缺口 | 模型输出不得启用方案；旧来源结果不能成为新版原文的有效草案 |
| S03 | 用户编辑、确认首项行动与开始时间、保存退出 | 正在审阅非权威草案 | 保存草案和明确确认内容，允许非关键信息未知 | 保存退出不等于启用；整体确认不能替代首项行动和时间的明确确认 |
| S04 | 用户修改原文 | 原文已有版本及关联草案 | 保存新版来源，旧版草案及未确认建议被取代 | 不使旧草案继续拥有当前来源的确认资格 |
| S05 | 用户在变更确认界面最终启用 | 来源和草案版本有效；关键缺口已解决；首项行动与时间已确认 | 原子发布不可变方案版本、设置当前版本、建立首项行动及执行安排；事实为“方案已启用” | 未确认、版本冲突或保存失败时均不部分生效；预计时长缺失本身不阻止启用 |
| S06 | 模型不可用或用户稍后重试／更换模型 | 设置尚未完成 | 保留已保存原文与草案，明确未完成状态 | 不由失败或更换供应商自动启用方案；不丢失已有权威状态 |

## 二、开始干预与执行安排

依据：已确认开始路径和无回应路径、ADR-0026、ADR-0045、ADR-0051、ADR-0052、ADR-0054。

“有效操作上下文”同时要求对象身份、状态版本、安排和干预仍允许该操作；仅旧通知仍可见不能证明操作有效。

| ID | 触发者与操作 | 前置条件 | 同事务结果及事件事实 | 拒绝条件／不发生的事 |
| --- | --- | --- | --- | --- |
| A01 | Core 到达计划开始时间 | 已确认安排适用，且没有对应开始、完成或改期记录 | 为该安排取得或建立唯一开始干预，按策略形成首次送达尝试 | 不为重复调度、多载体创建多个逻辑干预；不能绕过干预策略 |
| A02 | 设备桥接返回送达结果，Core 核验并记录 | 核对所引用的送达尝试及对应许可、设备结果；迟到结果按 ADR-0057，不仅凭当前用户操作已失效就推断过去未送达 | 保存符合条件的历史送达事实；同一逻辑干预至多计一次合格机会 | 不恢复旧操作或再次呈现，不从用户回应反推送达；未知时间不以接收时间冒充；重复回执不重复计数 |
| A03 | Core 在宽限结束检查一次跟进 | 没有明确回应，且尚未用过第二次尝试 | 同一干预的第二次且最后一次较弱送达尝试 | 安静时段、PC 离线或下一项计划工作已开始时失效，不延迟补发 |
| A04 | 用户打开开始入口，但取消或尚未确认所需时长 | “立即开始”或“我已经开始”需要确认时长 | 不建立会话和检查点；开始干预继续未决 | 不能把入口点击当成已开始、已解决或首要成功行为 |
| A05 | 用户最终确认“立即开始” | 有效操作上下文，无活动会话；有适用且已确认的预计时长，或本次已确认 | 原子建立执行中会话及首次检查点，解决开始干预、取消其剩余送达；事实为“执行会话已开始”，保留进入来源 | 已有活动会话、安排已改期／结束、行动已完成或上下文过期时不创建 |
| A06 | 用户最终确认“我已经开始” | 同 A05，且明确确认从现在起多久后检查 | 原子建立执行中会话及首次检查点，解决开始干预；进入来源为用户报告已经开始 | 实际开始时间保持未知，不要求补充大致开始时间；不能复用旧估时来跳过剩余时长确认 |
| A07 | 用户报告“我已经完成” | 有效开始上下文、行动未完成且无活动会话 | 原子记录完成报告、结束安排和干预、建立等待收尾的回顾式会话 | 无检查点，不伪造实际时间，不计入促成进入行为；已有会话时不能新增回顾式会话 |
| A08 | 用户确认“改到具体时间” | 当前安排及操作仍有效，新时间已明确确认 | 旧安排结束为已改期，同一行动建立后继安排，旧干预及剩余送达失效；事实为“执行安排已改期” | 不修改行动范围、不覆盖原时间；任一步失败保留旧状态 |
| A09 | 用户确认“今天不做” | 当前安排和开始干预仍有效，行动未完成 | 当前安排结束，保存本次不执行决定，解决干预并失效其剩余送达和界面 | 不创建会话、检查点、收尾或恢复包；不自动安排明天或顺延其他安排 |
| A10 | Core 到达未决开始界面期限 | 未获有效解决；期限按执行窗口、计划开始加预计时长、否则本地次日零点依次确定 | 关闭过期操作面，保留送达、未回应和未知结果事实 | 不补记执行、不标完成／失败／放弃；未执行主动尝试不能再发送 |

ADR-0052 的“回应解决同一干预”指完成相应确定性操作的有效提交，不取消已确认的 A04 边界。各载体操作的是同一权威上下文；界面打开、浏览和未确认输入不能绕过提交条件。

A02 的历史记录规则见 [ADR-0057](../adr/0057-allow-late-delivery-facts-without-reopening-actions.md)及其部分替代决定 [ADR-0058](../adr/0058-allow-inflight-delivery-result-commit-after-host-restart.md)。原 Core 在同一结果事务内核对关联、可靠确认旧宿主实例仍存活后，允许该事务在随后宿主重启时完成；检查时已退出或依据不足则拒绝新增结果。回滚后的新事务不能继承检查资格，新 Core 不补存旧未提交结果；已提交的相同原命令按幂等规则返回。历史报告不改变会话、调度或旧用户操作有效性；顺序未知不计机会或精确延迟，接收时刻不冒充发送时刻。

## 三、会话、检查点与收尾

依据：已确认执行与无回应路径、ADR-0022、ADR-0023、ADR-0044、ADR-0046～0049、ADR-0051。

| ID | 触发者与操作 | 前置条件 | 同事务结果及事件事实 | 拒绝条件／不发生的事 |
| --- | --- | --- | --- | --- |
| E01 | Core 到达检查时间 | 会话执行中，该检查点仍为当前且有效 | 核对该检查点，提供完成、继续并确认下一检查时间、暂停三类操作 | 不把到点解释为完成；检查点前不周期性追问 |
| E02 | Core 处理检查点无回应 | 当前检查点尚未解决、未到保留期限 | 最多一次较弱确认，之后只保留被动操作 | 不自动续行、不创建后继检查点、不从沉默推断结果 |
| E03 | 用户继续并确认下一检查时间 | 执行中，目标是有效当前检查点 | 旧检查点记录已回应并继续，同一会话建立唯一后继；事实为“检查点已续接” | 不能覆盖旧检查时间或新建会话；未确认时间不创建后继 |
| E04 | 用户报告完成或暂停 | 目标会话执行中；可在检查点前操作 | 保存明确报告，会话进入等待收尾，检查点失效；事实为“完成已报告”或“暂停已报告” | 继续占用唯一活动位置；不能再续接旧检查点 |
| E05 | 用户完成收尾 | 会话等待收尾 | 原子固化确认结果及最小执行证据，暂停时保存恢复包，结束会话并释放位置 | 部分完成不使整个行动完成；不得覆盖原报告或既有历史事实 |
| E06 | 用户跳过或关闭收尾界面 | 会话等待收尾 | 依据此前明确的完成／暂停操作原子保存最小证据、必要恢复包并结束会话；记录显式跳过 | 不强制补齐可选字段，不伪造实际用时、进展或精力 |
| E07 | Core 到达自动跳过边界 | 仍等待收尾；按 ADR-0047 的最早适用边界 | 与 E06 相同的最小收束结果，另记录自动跳过事实 | 不新增主动提醒；不是自动完成，也不能把未知状态先变为暂停再收尾 |
| E08 | Core 到达检查点无回应保留期限 | 会话仍执行中，当前核对仍未解决 | 会话跟踪结束、结果未确认，相关操作失效并释放活动位置 | 不进入收尾、不产生执行证据或恢复包，不宣称现实执行已经结束 |
| E09 | 用户更正已保存执行事实 | 明确指出历史事实及更正内容、原因 | 追加带时间的执行事实更正，保留原始事实 | 不覆盖、删除原证据或改写方案版本；不能由 LLM 自动更正 |

唯一活动位置适用于普通会话和回顾式会话。“执行中”和“等待收尾”均占用；已结束和会话跟踪结束均不占用。完成固化只适用于确切版本下的行动；部分进展可用于之后的同一行动安排，但不授权自动追加工作。

## 四、恢复、前台上下文与重启

依据：已确认恢复和上下文竞争路径、ADR-0012、ADR-0047、ADR-0049、ADR-0050、ADR-0053、ADR-0056。

| ID | 触发者与操作 | 条件与结果 | 不得发生的转换 |
| --- | --- | --- | --- |
| R01 | Core 启动、唤醒或恢复检查 | 从当前权威记录读取；恢复有效调度；离线错过的主动尝试失效；尚有未收束上下文时取得至多一个恢复干预，记录来源及版本 | 不逐条补发，不删除行动，不重放全部事件以重建权威状态 |
| R02 | Core 再次核对恢复上下文 | 来源未变复用；相关来源改变使旧记录失效，仍需要支持才生成新记录 | 不因重启重复主动创建同一上下文；旧版本操作不能作用于新记录 |
| R03 | 用户继续尚有效的活动会话 | 返回同一会话及有效检查点／被动核对，继续受其原有生命周期约束 | 不消费恢复包，不新建第二个会话，不仅因为重启重新计算一段预计时长 |
| R04 | 用户从恢复包继续并确认剩余时长 | 包未使用、未归档、目标行动未完成、无活动会话；原子创建当前时间的新安排、新会话、首次检查点，并标记包被新会话使用 | 不重开原会话，不部分消费包；旧版本行动不使旧方案重新成为当前版本 |
| R05 | 用户选择按当前计划继续，来源是未使用恢复包 | 按当前有效上下文校验，旧包未使用归档；原暂停事实及进展保留；实际建立新会话仍须满足 A05／A06 的时长与唯一性条件 | 归档不表示完成／失败／放弃，不自动迁移旧行动；来源是仍执行中的会话时适用 R09，不套用归档规则 |
| R06 | 用户选择“处理上一项” | 只有错过开始且没有开始证据时采用这一入口；展示确切行动及当前允许处理方式 | 不能声称有执行断点，不能重新使已过期开始干预有效，也不能伪造会话或执行补记 |
| R07 | 用户暂不决定 | 停止本次主动呈现，保留安静的主窗口被动恢复入口；不修改执行事实，再操作仍须重验来源版本 | 不把暂不决定写成暂停／放弃；不因反复打开或重启重新催促同一未变化上下文 |
| R08 | 下一项计划工作到达 | 旧未决开始界面保留在主窗口至原期限，停止其置顶呈现和跟进；置顶优先活动会话，否则最新到期行动 | 不提前删除旧未知事实，不通过前台切换创建第二会话 |
| R09 | 恢复时用户明确确认从旧执行中会话切换至当前计划，并确认新检查时间 | 旧会话未到跟踪截止，恢复来源、目标行动及安排均有效；同事务结束旧跟踪、失效旧检查点和待执行核对、建立新会话及首次检查点、保存恢复选择；旧退出原因为“用户选择切换”，新进入来源为恢复切换 | 旧结果保持未知，不生成旧收尾、执行结果证据或恢复包；取消／确认不全／校验或保存失败不部分切换；不能适用于等待收尾或已经结束的旧会话 |

R05 中选择执行上下文不等于会话已建立。R06 中查看及处理入口也不等于提交旧开始干预。界面导航不得取代相应领域操作的前置校验；本矩阵不扩展历史补记或方案自动重排。

### 重启核对表

| 重启时已提交状态 | 应恢复的结果 | 不应恢复或生成的内容 |
| --- | --- | --- |
| 原文／草案，未启用 | 保存的工作区及来源关系 | 自动启用或调度 |
| 已启用方案、未来安排 | 同一方案、行动与安排的有效调度 | 新方案版本或重复安排 |
| 送达尝试已错过／被动开始界面尚有效 | 尝试失效但保留有效被动操作；必要时一个恢复干预 | 原样补发错过的主动联系 |
| 开始界面已过期 | 过期及未知事实、适用恢复入口 | 原操作面、执行补记或失败结论 |
| 执行中会话、检查点仍适用 | 原会话及仍有效调度／核对 | 因重启新建会话或重置时长 |
| 检查点无回应保留期限已过 | 幂等执行 E08，结果继续未知 | 伪造暂停、恢复包或执行证据 |
| 等待收尾、尚未到退出边界 | 恢复等待收尾并继续占用位置 | 静默释放位置 |
| 等待收尾、退出边界已到 | 幂等执行 E07，只固化此前明确事实 | 重复证据或再次收尾提醒 |
| 恢复包已使用／未使用归档 | 原包与对应事实，拒绝重复使用 | 自动迁移、重新启用或消费第二次 |
| 转换已提交但客户端未收到结果 | 同一命令 ID 返回已存结果 | 第二个会话、事件或调度 |
| 显式恢复切换已提交 | 旧会话跟踪已结束且结果未知，新会话及检查点恢复；只占用一个位置 | 重开旧会话、重新执行旧核对或再次切换 |
| 转换未提交 | 事务前的完整状态 | 半个方案、孤立检查点、已消费但无接续会话的包 |

## 五、通用非法转换与竞态判据

| 场景 | 必须保持的结果 |
| --- | --- |
| 同一命令重试，包括 Core 重启后重试 | 返回原处理结果；不重复事件、证据或调度 |
| 不同命令争用同一旧状态，例如开始与改期、续行与完成 | 以 Core 当前状态及版本校验；已不合法的后续操作拒绝，不各自成功形成矛盾状态 |
| 陈旧通知、旧检查点、旧恢复上下文上的操作 | 不因载体仍可见而有效；拒绝并返回当前可用上下文 |
| 新建会话操作遇到已有活动会话 | 普通创建拒绝；R09 只能在同一事务内收束符合条件的旧执行中会话再创建新会话，不能形成两个活动会话 |
| 任一联合转换中途失败 | 全部回滚，旧状态及尚未消费的依据保留 |
| LLM 建议、模型响应或供应商更换 | 不直接修改权威状态；模型不可用不阻断已经启用后的确定性执行闭环 |
| 沉默、离线、主动联系失效 | 只保存对应系统事实，不推断用户未执行或失败 |

时间解析与既定期限校验的代码实现、事务锁和错误类型属于实现选择；实现必须遵守已有时间边界和上述结果，不得借此改变产品期限或增加状态推断。

## 六、恢复转换的补全记录

### U01：已解决——恢复时仍有效的旧活动会话让位于当前计划

Q38 已确认第 1 项，见 ADR-0056 与 R09：只有用户明确确认切换和新检查时间才联合提交，旧会话跟踪结束但结果未知，新会话及检查点同时建立；用户取消或提交失败不部分生效。记录切换操作事实不能推导旧行动的执行结果。

R09 必须重新校验旧、新两侧及恢复来源版本；例如旧会话已经被其他合法操作转入等待收尾，旧切换请求应拒绝，不能用未知结果覆盖明确报告。未确认期间旧会话仍受既定期限约束，不因打开切换入口暂停时间规则。

U01 不再占用主 grilling。矩阵已通过与 B-02、相关 ADR 的规范与需求双轴复核，并随 PR #28 合并（`930746d`）；对应验收场景见 [B-04](mvp-acceptance-scenarios.md)，整体就绪状态以[构建就绪门槛](mvp-build-readiness.md)为准。
