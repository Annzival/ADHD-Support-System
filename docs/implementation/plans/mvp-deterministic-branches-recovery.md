范围内与完成映射：

| 工作包（顺序 checkpoint，不是新增产品阶段） | 完成条件 | 验收来源 |
| --- | --- | --- |
| 开始分支、送达与期限 | 已开始、回顾式完成、改期、今天不做、一次较弱跟进、未决期限和单一前台均有 Core 命令及可操作桌面入口 | EX-01～10；A01～10、R08 |
| 会话、收尾与历史 | 续行保留检查点后继链；暂停及最小恢复包、显式／自动收尾、未知跟踪结束、旧版本引用和追加事实更正均守住唯一位置及不可回写事实 | SES-01～07；E01～09 |
| 恢复与正式桌面整合 | 同一会话恢复、一次性恢复上下文、包使用／归档、R09 原子切换可操作；真实通知返回正确上下文，五项宿主能力及 PC 重启回归 | REC-01～12、DESK-01～05；R01～09 |

范围外：I-03 的真实原文导入、审阅、最终启用和 LLM／PydanticAI 集成；I-04 的观察准入；完整方案调整、补记、日终复盘、剩余精力、再触达、邮件、桌面活动推断、Web/PWA、多端／服务器、公开分发。仍使用明确标识的隔离开发夹具，不开始正式 dogfooding。

## 实施与验收边界

- 权威状态、期限、干预策略、调度、恢复及更正规则全部在 Python Core。桌面宿主仅保留传输工作与设备桥接职责；前端草稿不是权威事实。沿用 SQLite 当前记录、成功事件、命令结果及必要调度同事务保存。
- 用受控时钟和隔离夹具覆盖窗口缺失、估时缺失、本地零点、安静时段、多个安排／方案版本及过期上下文；不让 I-01 的固定 4 小时测试窗口成为产品默认值。真实方案导入仍由 I-03 验收。
- 版本、关联和前置条件以领域矩阵为准；执行者可选择 schema／模块／接口实现，不可用 UI 禁用替代 Core 校验，或用重建夹具冒充同库重启恢复。
- 原有 Go 送达丢包测试和两个页面的收尾草稿回归继续保留。交错证据已在 PR #35 回传；按 ADR-0057 细化迟到结果的依据、时间与重启边界，再将诊断转为验收。不得用“用户开始了”推断已送达，或直接放宽所有旧版本命令；尚不明确的接纳条件返回治理，不把原则接受当作细节全部批准。
- Linux 负责实现、领域／协议／浏览器自动测试及构建检查；Windows 负责真实通知、焦点、小窗、托盘、单实例、开机启动、进程守护和 PC 重启证据。每轮记录源码 commit、二进制哈希、环境和数据库身份，不能用旧 spike 或 I-01 实机 PASS 替新实现填写 PASS。
- 使用 I-01 已验证的 Windows 10 22H2 x64、Python 3.12.3 x64、Go 1.25.0、Wails beta.8 和 Fixed WebView2 151.0.4129.78。需要升级或改变环境时先提交原因与证据，不静默外推。

现有回归入口（仓库根目录，依赖准备见[运行说明](../README.md)）：


以上是已有测试入口，不代表已有 I-02 覆盖；实现者增加相应测试后，提供“场景／参数 → 测试或人工步骤 → 结果证据”的映射。I-02 Windows 脚本和命令目前尚未实现，由执行 session 交付可复制步骤、预期现象、结束／清理方式及脱敏证据收集方法；不要立即运行交接报告中拟定的 `-Stage I02` 并声称成功。
